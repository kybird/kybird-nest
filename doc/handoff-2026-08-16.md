## 1. 왜 이걸 했나 — 우선순위 재정렬

brief.md 6장의 "만드는 순서"(1~6단계)는 **개발 루프 하나만 있다고 보고 그린
것**이다. 0장이 추가되면서 "다음에 뭘 하냐"의 답이 바뀌었다:

- 6장 기준 다음 = 5단계(대시보드) · 6단계(평가 하네스)
- 0장 기준 다음 = QA 루프

QA 루프를 얹으려면 **기각이 상류로 되돌아가는 경로**가 먼저 있어야 한다. 그게
없으면 루프를 만들어도 순환이 닫히지 않는다. 그래서 6장에 "재정렬" 절을 새로
넣고, 4.5(기각 경로) → 4.6(회귀 계기판) → 4.7(QA→기획 루프) → 4.8(오프피크
무인 기동) 순서를 명시했다. **실제 구현은 작은 4.6 부터 했다** — 싱크 스키마를
안 건드리는 변경으로 이 코드베이스의 표면 전파 경로를 먼저 확인해두면 4.5 가
안전해지기 때문이다.

### 2.2 회귀 계기판 (brief.md 4.6)

**문제**: `regressCount` 를 기록만 하고 **읽는 쪽이 없었다.** 카드마다 `↺N` 은
찍히지만 그건 카드를 하나씩 봐야 눈에 들어온다. 0장이 말한 "수렴 안 함" 신호가
아무한테도 안 갔다.

**핵심 설계 판단 — 왜 shared 인가**: 계산을 `@kybird/core` 에 두면 웹 대시보드가
못 쓴다(core 는 `better-sqlite3` 를 끌고 온다). 필요한 건 `Card` 뿐이라
저장소를 모르는 `@kybird/shared` 가 맞는 자리다. **CLI 와 웹이 같은 임계치로 같은
판단을 해야** 계기판이 신뢰된다 — 표면마다 따로 세면 두 화면이 다른 말을 한다.

- `packages/shared/src/regression.ts` — `regressionReport(cards)`, `REGRESS_STALL_THRESHOLD = 3`
  - 임계치 3의 근거: 1회는 흔한 재작업, 2회도 그럴 수 있다. 3회부터는 카드
    정의(범위·완료 조건)나 접근 자체를 의심할 자리다. **정밀한 수치가 아니라
    사람 눈에 띄게 하는 문턱**이므로 실사용 데이터가 쌓이면 조정해라.
  - 삭제된 카드(툼스톤)는 안 센다 — 지운 카드의 회귀는 개입 대상이 아니다.
- `packages/core/src/kanban.ts` — `boardRegressionReport(view)` (BoardView → 카드 목록 어댑터)
- CLI: 보드 하단에 요약 + 임계 초과 경고. **회귀가 없으면 아무것도 안 쓴다**
  (조용할 때 조용해야 시끄러울 때 읽힌다)
- 웹: 상단 배너 + 카드 배지가 임계치에서 amber → red 로 승격

### 2.3 기각 경로 (brief.md 4.5)

**설계 판단 두 개를 먼저 읽어라. 이게 이 기능의 전부다.**

**(가) 새 엔티티가 아니라 `Card` 필드로 갔다.** 기각은 이미 있는 완료→비완료
전이(`regressCount` 가 세는 그것)에 *주체*와 *사유*가 붙은 것이다. 별도 엔티티는
싱크 배관(`ENTITY_KINDS`, 서버 라우트, 스토어 테이블)을 통째로 하나 더 만들어야
하는데, 지금 필요한 건 "다음 루프가 무엇을 보고 행동하는가"고 그건 **최신 기각**
이면 충분하다.
→ **대가: 기각 이력이 안 남는다.** 횟수는 `regressCount` 가 세지만 "3번째 기각의
사유"는 복원 못 한다. 필요해지면 append-only 엔티티로 승격하면 되고, 그때 싱크
배관이 하나 는다.

**(나) 주체를 기록하고 목적지는 컬럼으로 뒀다.** 지금 보드가 하나뿐이라 QA
기각도 개발 기각도 갈 곳은 "할 일"이다. 누가 집어야 하는지는 `rejectedBy` 가
가른다. 루프별로 컬럼을 나누게 되면 `toColumnId` 만 주면 되고 핵심 함수는 안 바뀐다.

**추가 규칙**: **완료에 다시 도달하면 기각을 지운다.** 안 지우면 이미 고쳐진
사유를 다음 루프가 읽고 또 손댄다. core 와 서버 양쪽 `moveCard` 에 같은 규칙이 있다.

**스키마** (`Card` 에 3개 추가, 전부 nullable):

| 필드 | 타입 | 뜻 |
|---|---|---|
| `rejectedBy` | `"qa" \| "dev" \| null` | 마지막으로 기각한 루프 |
| `rejectedReason` | `string \| null` | 왜 튕겼는지 (**필수** — 비면 거부) |
| `rejectedAt` | `number \| null` | 기각 시각(ms) |

- 상류 결정: `cardRejectionOwner(by)` — `qa` → `dev`, `dev` → `plan`
- 서버는 `rejectedBy` 를 **enum 이 아니라 String** 으로 들고 있다. brief.md 3장
  "서버는 저장소다"에 맞췄다 — 루프가 늘어도 서버 마이그레이션이 필요 없다.
  프로토콜로 올릴 때만 `parseRejectedBy()` 로 좁히고, 모르는 값은 null 로
  떨어뜨린다(낯선 값 하나 때문에 pull 전체가 깨지면 안 된다).

**표면**:

```
knest reject <카드> "<사유>"            # QA 기각 → 개발이 받는다 (기본)
knest reject <카드> "<사유>" --as dev   # 개발 기각 → 기획이 받는다
knest reject <카드> "<사유>" --to <컬럼>
```

- MCP: `kanban_reject_card` (설명에 "그냥 move 로 되돌리면 사유가 안 남는다"를 명시)
- 웹: 카드 모달의 "기각해서 되돌리기" + 카드 앞면에 사유 미리보기
  (모달을 열어야만 보이면 아무도 안 읽고, 그러면 기각이 이동과 같아진다)

### 2.4 작업 중 발견해서 같이 고친 것

이번 작업의 부산물이지만 독립적으로 의미가 있다.

1. **`Rejection` 이름 충돌** — `packages/shared/src/sync.ts` 에 이미 `Rejection`
   이 있는데 그건 **서버가 push 를 거부한 것**(stale / missing_parent / forbidden)
   이라 카드 기각과 완전히 다른 개념이다. 내 타입을 `CardRejectedBy` /
   `cardRejectionOwner` 로 좁혔다. **이 둘을 헷갈리지 마라.**
2. **`apps/server/lib/board.ts` 의 5중 복붙** — Prisma 행 → 프로토콜 `Card` 변환이
   다섯 군데에 복사돼 있었다. 필드가 하나 늘 때마다 다섯 곳을 고쳐야 했고, 한 곳을
   빼먹으면 **그 경로로 쓴 카드만 조용히 필드를 잃는다.** `asCard()` 하나로 합쳤다.
3. **`packages/cli/test/mcp.mjs` 에 박힌 Windows 절대경로** (`D:/Project/...`) —
   이것 때문에 이 테스트는 macOS/Linux 에서 **아예 실행이 안 됐다.** 파일 기준
   상대경로로 고쳤다.
4. **한국어 조사 오류** — "개발가 받는다". 루프 이름마다 받침이 달라서
   (`QA가` / `개발이` / `기획이`) `LOOP_SUBJECT` 를 따로 뒀다.

### 4.2 다음 기능 — 4.7 QA 루프 (설계 결정이 먼저)

**시작하기 전에 정해야 한다**: 루프를 어디서 돌릴 것인가?

| 안 | 내용 | 대가 |
|---|---|---|
| A. 에이전트 세션이 knest 를 호출 | 지금 `backfill` 과 같은 형태 — knest 는 재료를 뱉고 에이전트가 판단 | 새 의존성 없음. 0장의 "Z.AI를 주 워커로"와 맞음 |
| B. knest 안에서 LLM API 호출 | 루프가 자족적으로 돔 | **이 코드베이스엔 LLM 클라이언트가 없다.** API 키·오프라인 정책이 전부 새 문제 |

확인한 사실: `backfill.ts` 는 LLM 을 부르지 않고 커밋 재료를 텍스트로 뱉는다.
`embedding.ts` 만 로컬 transformers.js 를 쓴다. **즉 지금 이 레포에 LLM 호출
경로는 존재하지 않는다.** brief.md 2장의 "훅에서 LLM 부르면 `--no-verify` 로
꺼버린다"는 판단과도 A 안이 결이 같다.

QA 를 기획보다 먼저 하는 이유: 입력(완료 카드)이 이미 실제로 쌓이고 있어서 당장
검증 가능하다. 기획 루프는 입력이 사람 의도라 더 모호하다.

## 5. 검증 방법

```
# 단위 테스트 (회귀 계기판)
npm run test -w @kybird/shared              # 13/13

# MCP 통합 테스트 — 빈 스토어 + git 레포를 전제한다
KYBIRD_HOME=<빈 경로> PROJ=<git 레포> node packages/cli/test/mcp.mjs    # 26/26

# 서버 (타입체크 포함)
cd apps/server && DATABASE_URL="file:<경로>" npx next build
```

**주의 두 가지**:
1. `npm run typecheck -w @kybird/server` 는 `layout.tsx` 에서 `LayoutProps` 를 못
   찾는다고 항상 실패한다. **버그가 아니다** — Next 가 빌드 때 생성하는 전역
   타입이라 `tsc` 단독으로는 없다. `next build` 로 확인해라.
2. MCP 테스트는 **빈 스토어**를 전제한다(완료 컬럼 카드 수를 정확히 센다).
   기존 스토어로 돌리면 엉뚱하게 실패한다.

수동 확인:

